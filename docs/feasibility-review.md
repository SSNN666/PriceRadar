## 1. 总评与结论

### 1.1 一句话结论

**作为简历项目：高度可行，素材质量高于绝大多数学生项目；作为上线产品：有 4 个真实问题，全部可通过降级修正解决，不致命。**

策略主线：**把不可控项（小程序审核、平台跳转、第三方转链）移出关键路径；用可控项（到手价引擎、同款匹配、Agent 编排、API 层、MCP Server）承担简历叙事。**

### 1.2 分维度评级

| 维度 | 评级 | 结论 |
|---|---|---|
| 简历价值 | ✅ 很高 | 「四层消歧」「LLM 不算钱」「合规数据层」叙事稀缺，覆盖 AI Agent + Python 后端两条线 |
| 技术可行性 | ✅ 高 | 全部组件有成熟方案；工作量集中在数据接入与同款匹配 |
| 数据接入 | ⚠️ 中 | 京东/拼多多个人可接入（已核实）；淘宝依赖第三方；个性化券存在口径缺口 |
| 合规性 | ⚠️ 中 | 框架正确（官方 API），但"到手价含返佣"存在内在矛盾，须修正 |
| 产品闭环 | ⚠️ 中 | 微信内淘宝跳转闭环不存在（行业普遍如此）；小程序有主体门槛 |
| 时间成本 | ✅ 可控 | 无投递时间压力下按质量推进；外部时钟（审核/备案/注册）需并行前置 |

### 1.3 三大必改项（摘要）

- **A. 到手价口径 + 返佣定位**：返佣必须移出用户到手价——"到手价含返佣"与"不做返利"矛盾且涉虚假宣传；北极星指标同步改口径。详见 §3。
- **B. 主体与端策略**：个人主体做导购必被驳回 → 个体工商户升为主路径；**MCP Server 从 P2 提前到 M1-M2**（无备案/审核/主体依赖）；小程序降为"条件交付"。详见 §5、§6.6。
- **C. 闭环降级**：跳转链路改为"京东/拼多多小程序跳转 + 淘宝复制口令"矩阵。详见 §4。

## 2. 数据层逐平台评估

### 2.1 京东联盟（✅ 可接入）

**核实结论**：
- 个人在 [union.jd.com](https://union.jd.com) 完成实名认证即可入驻媒体账号，**无需企业资质**；创建应用并申请商品查询接口权限，审核通常 1-3 个工作日。
- 个人账号基础权限频率约 5-10 QPS、日限额数千级；高级接口（实时销量等）需企业资质或联盟合作伙伴认证——本项目用不到。
- 商品查询类接口（`jd.union.open.goods.query` / `goods.detail.query`）可返回售价、优惠券、券后价、佣金比例。优惠券领取情况查询等部分接口需邮件向 `cps@jd.com` 申请权限。
  - *（2026-10-05 实测更正：`goods.search` 接口不存在（Invalid Method）；`goods.query` 为高级接口个人账号不可申请；京东侧实际可用主数据源为 `goods.jingfen.query`（京粉精选通道）——详见 [jd-api-findings.md](./jd-api-findings.md)）*
- ⚠️ **通道避免踩错**：必须走京东联盟开放平台，不要走宙斯（JOS）商家接口——后者需企业认证 + 卖家授权。

**关键限制**：
- 看不到真实库存数量（仅"有货/无货"）；
- 未参加联盟推广的商品查询不到；
- 公开接口返回的是**公开优惠**口径（见 §2.4）。

### 2.2 多多进宝（✅ 可接入）

**核实结论**：
- 个人开发者路径通畅：拼多多开放平台注册 → 开发者类型选"第三方开发者"、身份选"个人开发者" → 创建"多多客联盟"应用 → 登录多多进宝绑定 client_id → 推广位（PID）备案。
- 选品比价类接口（`pdd.ddk.goods.search` / `goods.detail`）对个人开放，零成本。
- 订单类接口（`order.*`）对个人关闭——本项目不需要，无阻塞。
- ⚠️ 部分渠道接口（如微信小程序场景的转链 API）需 PID 备案，未备案会报 `sub_code 60001`——M0 就把备案走完。

### 2.3 淘宝（⚠️ 依赖第三方，列为实验路径）

- 官方淘宝客 API（`taobao.tbk.*`）需媒体资质/等级门槛，**个人直连走不通**（与 v0.1 判断一致）。
- 折淘客/大淘营等第三方转链服务存在，按调用量计费，但：价格不透明、稳定性无 SLA、上游规则变化风险不可控。
- **评审结论**：淘宝继续留在 P0 会引入不可控依赖。建议 P0 只承诺**京东 + 拼多多**；淘宝走"第三方转链实验路径"（能跑通则加，跑不通降级为"粘贴链接仅解析展示"），核心叙事不依赖淘宝。

### 2.4 到手价数据口径缺口（重要）

v0.1 的到手价公式：`标价 − 店铺券 − 平台券 + 满减分摊 + 返佣`。

**核实结论（京东口径）**：
- 联盟接口能拿到：公开券列表（面额/门槛/有效期/剩余量）、部分满减/促销信息（`promotions` 含类型与金额）、券后价参考值。
- **拿不到**：PLUS 专享券、新客券、账号专属补贴、限时弹券等个性化权益；公开券后价 ≠ 用户结算实付价。

**修正要求（写入 v0.2）**：
- 到手价公式改为：`标价 − 公开券最优组合 − 满减（接口返回则计） → "公开优惠测算价"`
- 对比卡片固定附声明：**"基于平台公开优惠测算，未包含个性化券；最终以结算页为准"**
- 个性化券留"补录回路"（P1，设计见 [PRD §5.6](../PRD.md)）：手动输入或截图 VLM 识别（人工确认后参与计算），并借结算页实付价回填做校准——这反而是产品诚实的加分点
- 北极星指标：由"平均识别省钱额（含返佣）"改为"**平均识别省钱额（公开优惠口径）**"

## 3. 专题：返佣矛盾（必须最先决策）

### 3.1 规则事实

- 淘宝联盟自 **2013-01-01** 起禁止淘宝站内购物"返现金"给买家/会员；只允许非现金形式（积分/实物/优惠券），且积分不得可提现——间接返现同样违规，后果包括终止合作、佣金冻结。
- 京东联盟生态相对宽松（存在官方"京粉"返利形态），但第三方 App 自行向用户返现同样受联盟推广规范约束。

### 3.2 矛盾拆解

v0.1 同时写了：
- 用户故事 1："京东叠券+**返佣**后到手 ¥331"（返佣计入用户到手价）
- 6.1 节："联盟佣金归开发者（PID 绑定），**不做任何返利/提现**"

这两条无法同时成立：用户看到的"到手价"扣了返佣，但返佣被开发者拿走——**展示的是一个用户实际拿不到的价格**，构成误导；若真把返佣给用户，则触碰返利规则（淘宝侧明令禁止）与小程序的金融类目红线。

### 3.3 三个选项与推荐

| 选项 | 做法 | 代价 |
|---|---|---|
| **(a) 推荐** | 到手价不含返佣；报告不展示返佣金额；佣金归开发者（标准 CPS 模式） | 损失"含返佣"卖点——但它本来就是合规负债 |
| (b) | 完全不展示任何返佣相关信息 | 同 (a)，且少一个透明披露点 |
| (c) | 做官方返利形态（仅京东京粉等官方支持的平台） | 复杂化 + 淘宝侧禁止 + 金融合规风险，MVP 不碰 |

**结论**：选 (a)。连带修正 v0.1 第 1 节的差异化表述——**"返佣叠加"不是差异化，跨平台公开优惠口径的到手价对比、四层消歧、Agent/MCP 交互才是**。

## 4. 微信生态闭环（产品最大的真实约束）

### 4.1 跳转矩阵（v0.2 需写入 PRD）

| 平台 | 微信内跳转方式 | 状态 |
|---|---|---|
| 京东 | `wx.navigateToMiniProgram` 跳京东购物小程序（appId 公开：`wx91d27dbf599dff74`） | 理论可行，**需实测目标小程序是否接受外部来源跳转** |
| 拼多多 | 同上（跳拼多多小程序） | **需实测** |
| 淘宝 | **复制淘口令**（微信内无淘宝小程序，H5 也无法作为 web-view 业务域名） | 唯一合规路径；行业统一处理，非本项目缺陷 |
| Web 端 | 各平台推广链接直跳 | 无限制 |

### 4.2 web-view 技术限制（证伪 v0.1 的拼多多方案）

- web-view 打开网页必须配置**业务域名**，且需把微信校验文件放到目标域名根目录——**第三方平台域名无法完成该验证**（除非自建反代，属非官方灰色方案，不用）。
- **个人主体小程序禁用 web-view**。
- 结论：v0.1 5.4 节"拼多多走 web-view + 业务域名"方案不成立，替换为"小程序跳小程序；不成立的场景一律复制口令/链接"。

### 4.3 风控与处罚

微信对导购外链实施阶梯式处罚：首次封链接 → 重复违规封外链（7-30 天观察期）→ 恶意对抗永久封禁并拉黑主体。产品设计上避免"诱导性外链"文案，跳转入口保持中性（"前往比价"而非"点击领券"类诱导表述）。

## 5. 主体与类目

### 5.1 个人主体：不可行（已核实）

- 个人主体小程序**无电商/导购类目**，无法开通微信支付；
- 有实测先例：以"工具-信息查询"类目提交、**已屏蔽价格**的商品展示小程序，仍被驳回，理由为「核心内容涉及商业服务推广，个人主体小程序无适合该类目」；
- 个人主体还禁用 web-view。

**结论：v0.1 的"个人主体工具-查询类目尝试"预案删除**——提审周期是纯浪费，直接走个体工商户。

### 5.2 个体工商户：主路径（可行）

- **免费**、线上办理（各省政务服务网/App）、常见 0.5-5 个工作日办结；
- 材料：登记申请书 + 经营者身份证 + **经营场所使用证明**（多数地区支持住所信息申报承诺制；住宅地址可用性依当地政策）；
- ⚠️ 注意："仅通过网络经营"不能用域名/虚拟主机地址登记经营场所——需实际住所材料，注册前先查当地政策；
- 后续义务：30 日内税务登记；每年 1-6 月年报公示。
- 备案主体：服务器域名 ICP 备案建议**直接用个体工商户主体**（与小程序主体一致），注册完成后启动。

### 5.3 行动建议

个体工商户注册与 M1 开发**并行启动**（免费、不占关键路径）；小程序 M3 标记为**条件交付**——依赖主体注册 + 跳转实测，任一失败不影响项目完整叙事（Web + MCP 是兜底终态）。

## 6. 技术层评估

### 6.1 LangGraph 编排（✅ 可行，但叙事要补强）

**风险**：面试官必问"为什么不用单 Agent / 纯代码流程？"如果答不出，LangGraph 反而成为减分项（"为了用而用"）。

**v0.2 叙事补强**：状态机在本项目的真实价值——
1. **确定性节点 vs LLM 节点的边界显式化**：到手价引擎、同款匹配是确定性节点，意图理解/报告生成是 LLM 节点，状态图让这个边界在架构层可见；
2. **降级路径可枚举**：每个节点定义失败态（API 超时→单平台降级；匹配置信度低→标注近似款），状态机让分支显式可测试；
3. **可回放、可观测**：每个节点独立记 trace，支撑"P90 延迟拆解到节点"的量化叙事。

### 6.2 同款匹配：90% 准确率怎么做实（简历胜负手）

- "同款"必须先**定义**：同一商品在不同平台的同一 SKU（型号/代际/容量/颜色一致）。定义不清，准确率无从谈起。
- 必须构建**评测集**：200-500 对人工标注的跨平台同款/非同款对（含困难负例：同型号不同容量、同款不同代际、山寨相似款），报告 Precision/Recall 与分组（A/B/C）准确率。
- **评测集本身就是简历亮点**（"自建评测集"比"调了个 embedding"高一个段位），且是四层消歧每层单独消融实验的基础。
- 注意拼多多标题关键词堆砌噪声大，规格归一化规则需按平台分别设计。

### 6.3 到手价引擎（✅ 决策正确，值得加码）

"钱不由 LLM 算"是 v0.1 最正确的技术决策。加码方向：
- 券叠加规则的单测用例库（互斥券、门槛判定、`isBest` 最优券选择、满减分摊顺序），用例数进简历；
- 逐项列公式的输出设计保留（用户可核对），快照留痕保留。

### 6.4 价格快照冷启动（⚠️ 诚实但价值有限）

- 自采快照从上线日开始积累，第 30 天才有 30 个点；"时机建议"在早期基本没有统计意义——慢慢买类产品有多年历史库，本项目无法在"历史价格"维度竞争。
- **修正**：样本 <14 天只展示观测事实（"已观测 X 天，数据积累中"），不出分位数结论；"时机建议"定位为长期功能，不列为差异化的核心卖点。真差异化仍是跨平台到手价对比与消歧。

### 6.5 识图找同款（⚠️ 工作量被低估）

- 京东图搜物料（1 万次/日、需申请物料搜索权限）与阿里云图像搜索（淘宝联盟版，需付费 + 授权）均为额外审核/成本项；
- 拼多多无官方图搜，VLM 是唯一路线。
- **修正**：**VLM 单路优先**（Qwen-VL 识别 → 结构化关键词 → 联盟搜索 → 复用匹配管线），全平台覆盖、成本可控、不引入新审核项；图搜 API 降级为 P1.5 增强路径（京东优先）。v0.1 的"双路交叉校验"叙事可以保留为设计目标，但不作为 MVP 交付。

### 6.6 MCP Server：建议从 P2 提前（简历性价比最高）

- 无备案、无主体、无审核依赖，纯技术交付；
- 受众直接（Claude/Cursor 用户即开发者），GitHub 可积累 star 与调用量数据——简历上"有真实用户的 AI 工具"远比"又一个 Web demo"强；
- 与目标岗位（AI Agent / LLM 应用）匹配度最高。
- **建议提前到 M1-M2 交付**，成为与 Web 并行的一等公民。

| 内部工作 | 到手价引擎、匹配评测、LangGraph、API 层、Web、MCP | 全部可控，按质量推进 |

## 8. 竞品与差异化修正

| 维度 | 慢慢买/购物党 | 平台 AI | 开源比价 | **PriceRadar（修正后）** |
|---|---|---|---|---|
| 比什么 | 标价+券后价 | 生态内价格 | 标价 | **跨平台公开优惠口径到手价** |
| 跨平台 | 是 | 否/弱 | 是 | 是 |
| 数据来源 | 自建十年库 | 平台内部 | 爬虫为主 | **官方联盟 API（合规）** |
| 买入时机 | 有（历史库） | 无 | 无 | 自观测快照（诚实标注天数，早期弱） |
| Agent 化 | 否 | 有限 | 是 | LangGraph 编排 + **MCP Server** |
| 多候选消歧 | 无 | 无 | 无 | **四层漏斗（规则/向量/统计/LLM）** |

**修正点**：
1. 删除"返佣叠加"差异化——它是合规负债不是卖点；
2. "买入时机"承认冷启动弱势，定位长期功能；
3. 真差异化三件套：**跨平台到手价对比 + 四层消歧 + Agent/MCP 交互**。
4. 需求侧待验证：用户是否愿意为省几十块粘贴一次链接？——种子用户测试第一周就要验证这一点。

## 9. 风险矩阵 v2
